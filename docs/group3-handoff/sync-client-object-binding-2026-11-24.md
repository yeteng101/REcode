## 本轮目标

复用直接调用实参和队列来源，把注册函数的形参追溯到可确认的具名全局对象。当另一条访问路径也通过真实调用点绑定同一对象和同一字段时，导出调用方对象关联。身份来自编译器声明和调用点，队列回收该注册对象仍是可能来源。 [队列来源](sync-queue-provenance-2026-11-24.md)

HPR-048 固定 libuv 提交的 `test/test-async.c` 同时包含注册和发送，显式传入同一个文件静态 `async`。选择对应的单一 CMake 构建目标做静态分析，区分库自身构建和加入真实调用方源码的结果。库内还有经 `loop->wq_async` 等成员的调用，实例关系需独立证据。

本轮按具名全局存储进行关联。多个编译目标、自动对象的不同调用激活、未知参数和队列实例保留既有覆盖边界。输出需说明只有在取到该注册对象这一条件下，两处访问才共享对象。执行上下文、线程重叠、竞态结论和第三组接口沿用原有语义。

## 验收

1. 用真实 Clang 构造中性的库和调用方，验证注册和消费能与另一条访问绑定同一具名对象，另一个同类型对象与同名静态对象各自独立。
2. 通过正式 CLI 检查原生 JSON、稳定对象 ID 和证据链。与基线对照定向和全套测试。
3. 固定 libuv 提交和单一编译目标，静态核对库自身和加入 `test/test-async.c` 两种输入。记录 HPR-048 的调用点、声明、条件以及仍待建立的执行上下文。分支保留待审阅。
