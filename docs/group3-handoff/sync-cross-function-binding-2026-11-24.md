# REcode 跨函数字段绑定

- 基线 `sync-field-binding` 的 `ac35748`，继承本地 `group3` 的 `e52eedd`。
- 工作分支 `sync-cross-function-binding`。
- 状态 规划，2026-11-24。

## 目标

把已确认的函数内部字段访问沿直接调用边绑定到调用方的实参。先支持接收者指针原样转发、单定义局部指针复制和具名对象取地址。原生 JSON 保留调用点、实参来源、参数序号及字段访问的证据。具名全局对象沿调用边保留字段对象 ID。对参数和自动局部存储保留对应作用域。 [局部字段绑定](sync-field-binding-2026-11-24.md)

分析以已解析到的直接调用和编译单元为范围。无法确定定义、弱符号或重定向符号、重写和逃逸的指针、指针算术和内存间接载入保留未知。调用链限制深度和输出量，只有链路中共享的确切来源可供绑定。已有 `shared_objects`、线程上下文和第三组契约保持原有含义。

## 验收

1. 用真实 Clang 验证跨文件的两级调用、两个具名对象分别传参、参数或局部指针转发，以及重写、逃逸、间接调用和不明指针来源的反例。
2. 通过正式 CLI 检查原生证据及边界，跑现有语义同步、字段绑定和内存定向回归，并与基线比较全套测试。
3. 用 HPR-048 的固定提交静态验证 `uv__async_close` 到 `uv__async_spin` 的实参与字段访问。沿注册、入队和取出路径检查 `uv__async_io` 中 `h` 的证据。队列需要对象成员存取、跨调用副作用及容器地址恢复，如果直接调用规则无法证明链路，就记录能够证实的链路和第一个未知点。所有测试以通用规则为准。
