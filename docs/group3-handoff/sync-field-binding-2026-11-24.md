## 问题

HPR-048 的原子位置与 `pending` 成员位置已经可以分别导出。本轮补上其中可由 Clang AST 核查的一段链路，从 `&base->field` 经局部指针的赋值或复制，到普通解引用或原子目标参数。库调用方传入的指针、从队列取得的指针仍属于运行时实例。 [并发基础事实](sync-source-facts-2026-11-24.md)

## 实现与边界

在已有原生同步 JSON 下增加独立的 `field_bindings`。以 Clang 的字段声明、接收者来源和有效的局部指针赋值为证据。只有定义清楚覆盖使用位置、且局部指针没有重写或取地址逃逸时，才导出绑定。支持简单的地址赋值、指针复制、兼容的限定类型转换、普通解引用及已识别原子操作的对象参数。间接运行时接收者记录本次取地址所捕获的值。能确认的具名全局存储另外提供稳定字段身份。自动局部存储以函数调用为作用域。

当前阶段只处理函数内的通用链路。跳转、指针算术、类型重解释、未知写入和跨函数传参保留覆盖限制。不同捕获点可以指向同一字段声明，但需要额外证据才能归并为同一运行时对象。已有共享对象、执行上下文、同步保护推理和第三组消费契约保持原有含义。

每条记录包含字段声明、接收者声明、取地址、指针定义和访问位置。静态可确证的具名全局字段有 `field_object_id`。局部对象随调用分配，参数指针和局部接收者指针按取地址时的值描述。原子记录只绑定原子操作的主要对象参数。输出最多保留 512 条，每文件最多 64 条，单链最多跟踪 8 个指针定义。

## 验收

1. 用真实 Clang 的 C 样例验证同一字段声明下的两个独立全局对象、局部指针赋值与复制、未知参数接收者、原子目标和普通解引用。加入重写、逃逸与条件赋值的反例。
2. 用正式 CLI 确认新增 JSON 和证据引用。运行定向测试和基线对照。
3. 用 HPR-048 的固定提交静态核对 `uv_async_send`、`uv__async_spin` 和 `uv__async_io` 的原子操作与对应的字段捕获。记录尚未绑定的运行时关系和现有语义覆盖。分支单独保留以供审阅。

## HPR-048 结果

libuv `10902ab616058198067d6c2cc414014d36f86fff` 用 CMake 生成编译命令，Clang 19.1.7 成功读取全部 70 个编译单元。`src/unix/async.c` 的六处原子操作都追溯到 `uv_async_t` 的 `pending` 字段声明，证据位于 `include/uv.h:957` 的宏展开点。

| 函数 | 取地址来源 | 已连接的访问行 |
| --- | --- | --- |
| `uv_async_send` | 第 96 行 `&handle->pending`，接收者为函数参数 | 99、106、119 |
| `uv__async_spin` | 第 131 行 `&handle->pending`，接收者为函数参数 | 135、143 |
| `uv__async_io` | 第 207 行 `&h->pending`，接收者为局部指针 | 208 |

三处取地址分别关联各自捕获的指针值。跨函数的运行时对象相等性和事件循环的执行关系仍未知。现有语义同步仍为 `partial`，已绑定执行上下文的共享对象仍为 0。本轮为第一组静态验收，第三组候选及端到端验收未运行。

新增原生 JSON 在此案例有 6 条绑定，紧凑大小 8,119 字节，无条数截断。因跳转或内联汇编跳过 76 个函数，三个目标函数均得到验证。无法认出原子操作码的旧版 Clang JSON 仍可能缺少相应绑定。
