# REcode 字段指针绑定

- 基线 `sync-source-facts` 的 `0dc8ee84e060fcb548d0c6cb4ae1a939975a4d19`，其 `group3` 基线为 `e52eedd`。
- 工作分支 `sync-field-binding`。
- 状态 规划，2026-11-24。

## 问题

HPR-048 的原子位置与 `pending` 成员位置已经可以分别导出。本轮补上其中可由 Clang AST 核查的一段链路，从 `&base->field` 经局部指针的赋值或复制，到普通解引用或原子目标参数。库调用方传入的指针、从队列取得的指针仍属于运行时实例。 [并发基础事实](sync-source-facts-2026-11-24.md)

## 实现与边界

在已有原生同步 JSON 下增加独立的 `field_bindings`。以 Clang 的字段声明、接收者来源和有效的局部指针赋值为证据。只有定义清楚覆盖使用位置、且局部指针没有重写或取地址逃逸时，才导出绑定。支持简单的地址赋值、指针复制、兼容的限定类型转换、普通解引用及已识别原子操作的对象参数。间接运行时接收者记录本次取地址所捕获的值。能确认的具名全局存储另外提供稳定字段身份。自动局部存储以函数调用为作用域。

当前阶段只处理函数内的通用链路。跳转、指针算术、类型重解释、未知写入和跨函数传参保留覆盖限制。不同捕获点可以指向同一字段声明，但需要额外证据才能归并为同一运行时对象。已有共享对象、执行上下文、同步保护推理和第三组消费契约保持原有含义。

## 验收

1. 用真实 Clang 的 C 样例验证同一字段声明下的两个独立全局对象、局部指针赋值与复制、未知参数接收者、原子目标和普通解引用。加入重写、逃逸与条件赋值的反例。
2. 用正式 CLI 确认新增 JSON 和证据引用。运行定向测试和基线对照。
3. 用 HPR-048 的固定提交静态核对 `uv_async_send`、`uv__async_spin` 和 `uv__async_io` 的原子操作与对应的字段捕获。记录尚未绑定的运行时关系和现有语义覆盖。分支单独保留以供审阅。
