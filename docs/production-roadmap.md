## 六个工作方向（第 1–3 项已实现基础，其余待办）

### 1. 生产任务系统

- 持久化任务队列取代进程内 ThreadPoolExecutor。
- 任务状态持久化与服务重启恢复。
- 幂等提交、任务重试。
- 结果对象存储与过期清理。

### 2. 沙箱与安全

- 容器或轻量虚拟机隔离。
- 限制网络、CPU、内存、磁盘和进程数。
- 约束 git、cmake、clang 等命令的执行。
- 防止仓库内容中的 Prompt Injection。
- 禁止访问宿主机文件、密钥和评测 Gold。
- 生产环境默认关闭本地仓库路径。

### 3. 可观测性

- 完整 Trace 查看页面与统一 Dashboard。
- 任务成功率、工具失败率、各阶段耗时。
- token 成本、unknown rate、资源使用情况。
- 告警与日志审计。
- 现有 tool-trace.jsonl 是基础，不能视为已经具备统一可观测平台。

### 4. 发布工程

- 容器镜像固定、依赖锁定和 SBOM。
- CI/CD、Staging、Shadow、Canary。
- 自动回滚与版本兼容规则。
- 评测 baseline 通过只能证明研究和离线流程，不能证明服务可安全上线。

### 5. Agent 产品质量

- 函数指针与虚调用。
- 跨函数资源所有权与别名分析。
- atomic happens-before 与线程身份。
- 宏展开、builtin 和平台条件分支。
- 这些属于分析能力改进，不能仅以增加验证集替代。

### 6. 产品闭环

- 仓库 URL 提交页面与任务进度。
- 可视化预览和 JSON/HTML 下载。
- 失败原因展示。
- unknown 转人工复核，并记录反馈。

## 阶段完成判据

第一阶段应能够演示：任务持久化提交后，即使服务或 worker 重启也可恢复；重复提交和重试行为明确；结果可从对象存储读取并按策略过期；不可信仓库在隔离环境执行；完整 Trace 可供查看和定位问题。

继续完成监控、鉴权、限流、渐进发布与回滚后，才可将当前“本地 Agent 闭环”推进为可对外试用的生产服务。本文是工作计划，已完成项以上述更新为准，不是上线批准。
